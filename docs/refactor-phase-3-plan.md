## 2. 목표와 범위

AI 스터디 화면을 `js/features/ai-study/view.js`로 분리한다. 한 기능의 화면을 고칠 위치를 명확하게 하되 사용자 동작, 데이터 형식, 저장 시점은 유지한다.

대상 7개 메서드:

1. renderAiStudyEmptyState
2. renderAiStudy
3. openAiStudyModal
4. closeAiStudyModal
5. openAiStudyDetailModal
6. closeAiStudyDetailModal
7. copyAiStudySnippet

app.js에는 단일 store, AI 노트 CRUD/필터링, 중앙 저장·동기화, 이벤트 연결, 화면 전환, 초기화를 유지한다. CSS/HTML 본문 디자인, 기본 데이터 시딩, 암호화, 저장 키, localSync, Vault, 가계부는 변경하지 않는다. HTML 변경은 스크립트 연결과 관련 캐시 식별자에 한정한다.

## 3. 연결 방식과 주의점

- 기존 개발기록과 동일한 일반 script + 팩토리 방식을 사용한다. ES modules나 빌드 도구 전환은 별도 작업이다.
- 새 파일은 팩토리 정의만 한다. 로드 시 store 생성, 렌더링, 저장, 이벤트 등록, 통신을 실행하지 않는다.
- app.js에서 기존 store, DEFAULT_AI_STUDY_CATEGORIES, escapeHTML을 팩토리에 전달한다. 노트 배열을 복사해 보관하지 않고 렌더링할 때 기존 store의 최신 값을 읽는다.
- 기존 UI 객체에 메서드를 합성해 window.UI와 호출 이름을 유지한다. renderSidebar 등 this 호출은 기존 UI를 수신자로 유지한다.
- copyAiStudySnippet의 UI.showToast는 새 파일에서 app.js의 지역 UI를 직접 볼 수 없다. 호출 시 기존 UI를 참조하는 콜백(예: (...args) => UI.showToast(...args))을 전달한다. 팩토리 생성 시 UI.showToast를 즉시 읽으면 UI 초기화 전 참조 오류가 날 수 있으므로 피한다.
- document, navigator, window.sounds, 타이머 동작은 기존 의미를 유지한다. 함수 이름 변경, 화살표 함수로 일괄 전환, bind 일괄 적용을 섞지 않는다.
- 두 HTML 모두 새 파일을 app.js보다 먼저 읽게 하고 로딩 순서를 동일하게 유지한다.
- 메서드 중복 키, 누락된 script, 누락된 의존성은 테스트에서 실패시킨다. 오류를 숨기는 빈 메서드 대체는 하지 않는다.

## 4. 순서와 통과 조건

### 0단계: 작업 기준 고정

- 구현 승인 후 스냅샷을 기반으로 별도 codex/refactor-phase-3 작업 브랜치를 만든다. 이후 변경이 있다면 diff를 먼저 검토해 보존한다.
- 테스트가 실제 프로필/운영 서버에 접근하지 않는지 확인한다.
- 기존 AI UI 검사를 실행하고 가상 노트로 정상/빈 목록/검색 없음/동기화 미확인 상태의 기준을 기록한다.
- 기존 오류가 발견되면 분리와 섞지 않고 재현·별도 수정·검증 후 새 기준점을 만든다.

### 1단계: 상세 보기와 복사만 먼저 분리

- openAiStudyDetailModal, closeAiStudyDetailModal, copyAiStudySnippet 세 메서드를 이동한다.
- 새 팩토리를 기존 UI에 연결하고 두 HTML을 함께 수정한다.
- 상세 내용·줄바꿈·태그·코드·링크, 닫기, Esc, 복사 성공 및 기존 대체 복사 경로를 가상 데이터로 확인한다.
- 상세 보기와 복사가 업무 데이터 저장 또는 업로드를 만들지 않는지 확인한다.
- 전체 app.js를 실행하는 outbox 테스트에 새 파일 로딩을 반영한다. Node 및 실제 HTML 검사 통과 후 독립 커밋을 만든다.

### 2단계: 목록과 빈 화면 분리

- renderAiStudy와 renderAiStudyEmptyState를 같은 파일로 이동한다.
- 분류·검색·고정 표시·카운트·사이드바 연동을 확인한다.
- 노트 없음, 검색 결과 없음, 서버 확인 전 빈 상태가 기존과 구분되는지 확인한다.
- tests/ai-sync-ui.cjs는 현재 app.js의 문자열 구간을 추출한다. 해당 화면 부분만 새 실제 파일을 로드하도록 수정한다. 다른 테스트 전체 개편은 하지 않는다.
- 동기화로 노트 배열이 교체되어도 최신 수신 내용이 표시되는지 확인한다. 통과 후 독립 커밋을 만든다.

### 3단계: 작성·수정 모달 분리

- openAiStudyModal, closeAiStudyModal을 이동한다.
- 작성 기본값, 기존 노트 편집값, 포커스, 닫기, Esc 동작을 확인한다.
- submit/삭제/고정 이벤트와 store 메서드는 app.js에 그대로 둔다.
- 작성·수정·삭제·고정 동작 후 가상 저장소와 재실행 결과를 확인한다. 로컬 저장 실패 시 입력이 남고 성공 메시지가 나오지 않는지 확인한다.
- 테스트 중 기존 결함이 드러나면 분리 변경과 구분해 처리한다. 통과 후 독립 커밋을 만든다.

### 4단계: 통합 확인과 문서 정리

- 이동한 메서드가 새 파일에만 정의되어 있고 이벤트가 중복 등록되지 않았는지 확인한다.
- 두 HTML을 실제 script 태그로 로드하는 AI 화면 회귀 검사를 추가/확장한다. 기존 devlog-ui 검사는 연결 및 주변 기능 회귀 확인에 재사용한다.
- PC와 모바일에서 두 진입 HTML을 확인하고, 두 HTML의 file://에서도 AI 화면 진입과 모달을 확인한다.
- PROJECT_RULES.md의 파일 구조/검사 안내와 README의 해당 구조만 현재 상태에 맞춘다.
- 검증된 구현을 리뷰 가능한 상태로 보고한다. main 병합·배포는 별도 승인 후 수행한다.

## 5. 검증 명령과 완료 기준

현재 환경의 브라우저 검사 설정(PowerShell, 이 프로세스에만 적용):

```powershell
$env:AI_TEST_PLAYWRIGHT_PATH='C:\Users\JY\.cache\codex-runtimes\codex-primary-runtime\dependencies\node\node_modules\playwright'
node --test tests/local-load-safety.test.cjs tests/outbox.test.cjs tests/ai-sync.test.cjs
node tests/ai-sync-ui.cjs
node tests/ai-study-ui.cjs
node tests/devlog-ui.cjs
node tests/ui-performance.cjs
```

실행 경로는 이 PC에서 확인한 값이다. 다른 PC에서는 Playwright 및 Edge 설치 위치를 다시 확인한다. 기존 기준과 화면을 비교하려면 `AI_STUDY_BASELINE_PATH`를 해당 기준 JSON 경로로 설정한다. 이 변수를 생략하면 동작 회귀 검사만 수행한다. 기준 파일이 없는 경로를 지정하면 검사가 모두 통과한 뒤 새 기준을 기록하므로, 변경 후 새로 만든 기준을 분리 전 비교 결과로 간주하지 않는다.

완료에 필요한 관찰:

- 기존 화면/동작과 차이가 없고 브라우저 실행 오류가 없다.
- 실제 HTML 로딩 검사와 부분 코드 검사를 함께 통과한다.
- 표시·검색·모달 열기로 업무 데이터와 클라우드 쓰기 횟수가 바뀌지 않는다.
- CRUD 저장 흐름, 삭제 기록, 미전송 변경이 기존대로 보존된다.
- 실패한 업로드 → 재실행 → 오래된 서버 수신 → 재전송에서 로컬 변경이 유지된다.
- 같은 노트 충돌 시 양쪽 원문 보존과 다른 노트의 수신 표시가 유지된다.
- 실패 원인을 감추기 위해 assertion을 삭제하거나 기대 결과를 완화하지 않는다.

## 6. 중단과 복구

- 로딩 오류, 입력 소실, 예상 밖 저장/업로드, 충돌 데이터 변화가 하나라도 발생하면 다음 단계로 넘어가지 않는다.
- 문제 단계의 작은 커밋만 되돌리는 것을 기본으로 한다. 후속 단계가 의존하면 후속 커밋부터 역순으로 되돌린다.
- 작업 중인 파일을 보존하고 git revert 등 이력을 남기는 복구를 사용한다. reset --hard, 강제 push, 전체 파일 덮어쓰기는 사용하지 않는다.
- script 추가와 app.js 연결 변경은 항상 같은 복구 단위로 취급한다. 새 파일만 삭제하면 앱 초기화가 깨질 수 있다.
- 운영 배포 후 코드 복구가 필요하면 되돌린 JS와 두 HTML의 캐시 식별자도 함께 갱신한다. 소스 복구로 사용자 데이터를 되돌릴 수 있다고 가정하지 않는다.

## 7. 이후 개선 후보

이번 범위 완료 후 사이트 모음/연차관리처럼 의존성이 작은 화면을 같은 방식으로 검토한다. 기능별 이벤트 분리는 등록·해제와 중복 실행 방지 기준을 정한 별도 단계로 진행한다. 저장·동기화와 가계부·파일보관함 구조 변경은 더 뒤에서 설계한다.

js/ui.js와 js/store.js는 이름만 보고 현재 실행 경로라고 가정하지 않는다. 실제 두 HTML의 로딩 목록을 기준으로 판단하며, 오래된 파일 정리와 CSS/HTML 공통화는 이번 이동과 섞지 않는다.
