# 전체 자료 자동 병합

웹과 모바일에 각각 남아 있는 기록을 파일 이동 없이 중앙 동기화에서 합친다. 동일 ID의 동일 기록은 한 번만 반영하고, 다른 ID의 신규 기록은 함께 유지한다. 제목·날짜만 같은 별개 기록을 임의 삭제하지 않는다. 같은 기록의 서로 다른 수정본은 항목별 시각으로 선택하고 양쪽 원문을 보존한다. 월별 가계부는 기존 요청대로 PC 웹 기준을 유지한다.

## 동작

- 각 기기의 첫 병합 전에 주 저장 원문, 별도 저장 키, 보관함 파일을 IndexedDB에 보존한다. 서버에서 처음 읽은 원문도 보존한다. 이 보관은 중앙 업무 데이터와 분리된 복구용 사본이며 전송하지 않는다.
- 기존 중앙 목록에 보물 지식, 은행 내역, 분류 규칙, 활동 기록을 연결한다. 별도 저장 키는 지우지 않고 한 번만 가져온다. 이전 자체를 새 수정으로 취급하지 않는다.
- 전송 중 생긴 변경, 조건부 쓰기 412, 일시적 통신 실패는 자동으로 다음 시도를 예약한다. 서버 확인 전에는 미전송 기록을 해제하지 않는다.
- Firebase REST에서 암호화 IV의 변경 알림만 구독하고 실제 수신은 기존 암호화·ETag 경로를 사용한다. 연결 단절 시 재연결·30초 보조 확인·화면 복귀 확인을 사용한다.
- 500KB를 넘는 Vault 파일의 내용을 제거하던 처리를 없앴다. 실제 파일 내용까지 송수신하며, 메타데이터만 확인한 것을 파일 전송 성공으로 간주하지 않는다.
- 로컬 저장 실패도 지연 재시도한다. 재시도는 로컬 저장 확인부터 시작하며, 실패한 입력을 서버에 저장됐다고 처리하지 않는다. 용량·권한·다른 탭 변경과 동기화 처리 단계별 오류를 구분해 표시한다.
- 32KB를 넘는 복구 항목은 기존 IndexedDB 원문 저장소에 보관을 확인한 후 작은 참조만 `localSync.recovery`에 남긴다. 해당 원문은 설정의 원문 내보내기에 포함된다. 큰 첨부 수정본이 localStorage 용량을 중복 소비하는 것을 방지한다.
- 사진·가계부 파일 등 큰 첨부 원문도 중앙 저장 어댑터에서 IndexedDB에 확인 저장하고 localStorage에는 참조를 둔다. 메모 객체, 중앙 Store, 서버 암호화 형식은 유지한다. 서버 업로드와 내보내기에는 전체 원문이 들어간다. 앱 시작 시 참조의 원문·내용 해시를 확인하며, 구버전 앱이 참조를 본문으로 업로드하지 못하도록 쓰기를 차단한다.
- IndexedDB 열기·원문 보관·파일 읽기가 응답하지 않을 때 15초 뒤 실패를 표시하고 재시도한다. 완료되지 않은 보관을 성공으로 간주하지 않는다.

## 검증

- `node --test tests/*.test.cjs`: 저장 실패 복구 회귀 검사를 포함한다.
- `tests/full-sync-ui.cjs`: 두 HTML에서 가상 PC 2대와 모바일 1대, 실제 IndexedDB·암호화·로컬 SSE 서버로 자동 병합, 큰 파일 전송, 일시 실패 재시도, 삭제 후 재시작 검증.
- `tests/automatic-sync-ui.cjs`: PC·모바일·로컬 HTML, 수정본 보관, 저장 실패, 재실행, 원문 내보내기.
- `tests/sync-storage-recovery.test.cjs`: 일시적인 저장 실패 후 자동 재전송과 대용량 복구 원문 보관 실패 시 원본 유지. 브라우저 검사는 실제 localStorage 용량을 채우고 IndexedDB 보관 원문의 크기까지 확인한다.
- `tests/main-storage-ui.cjs`: 합성 첨부 540만 자로 기존 방식의 실제 `QuotaExceededError`를 재현하고, 새 방식의 양방향 메모 일치·첨부 전체 보존·오프라인 재실행·구버전 쓰기 차단·첨부 누락 시 보호를 두 HTML에서 확인한다. `STORAGE_REPRO_BEFORE=1`은 새 어댑터를 제외한 재현 모드다.
- 가계부 20개 화면 조건 및 AI 노트 8개 화면 조건 통과.
- 합성 성능 검사에서 변경 없는 확인은 사용자 본문 해시·복호화·저장·Vault 재읽기를 반복하지 않았다. 실제 기기나 운영 통신의 2초 성능 보장은 아니다.

## 적용과 복구

업데이트된 앱을 기존 자료가 있는 각 브라우저에서 열어야 해당 기기의 미전송 원문도 참여한다. 닫힌 모바일 브라우저의 저장소에 다른 기기나 서버가 직접 접근하는 구조는 아니다. 운영 데이터의 실제 병합 완료는 배포 성공과 구분한다.

원문은 각 기기의 `todolist_jy_sync_originals` IndexedDB와 `localSync.recovery`에 남고, 설정의 원문 내보내기에 포함된다. 문제가 있으면 저장소를 초기화하지 않고 원문·미전송 기록을 보존한 상태에서 후속 수정한다. 구버전 앱은 새 미전송 메타데이터를 이해하지 못할 수 있으므로 코드 롤백만을 데이터 복구로 간주하지 않는다.

현재 서버 전송은 기존 암호화 스냅샷 형식이다. 로컬 첨부는 IndexedDB에 분리하지만 기기 전체 저장 용량·서버 요청 크기·네트워크 오류 자체가 없어지는 것은 아니다. 해당 오류에서 완료를 표시하거나 원문을 버리지 않는다. 서버의 첨부 분리 저장과 레코드 단위 전송은 별도 후속 구조 개선이다.
